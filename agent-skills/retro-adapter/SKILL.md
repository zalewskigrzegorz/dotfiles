# `/retro` adapter

The `retro` plugin (netresearch/retro-skill) assumes skills in their own repos and rules in `~/.claude/CLAUDE.md`. Here everything is generated by chezmoi from `~/Code/dotfiles`, so ignore its default destinations:

| retro destination | Here |
|---|---|
| `personal-rule` | `agent-rules/<slug>.md` with `alwaysApply: true`, **only if it matters in most sessions** (instruction files share a 150k budget). Tool/task-specific → a skill in `agent-skills/`; dotfiles-only → `.claude/rules/<slug>.md` in the repo; work-monorepo-only → `agent-rules/scoped/<slug>.md` with `paths:` (off the budget, 0333c4c7) |
| `project-rule` | the rules file the repo already uses (`CLAUDE.md` in dotfiles, home-lab); `AGENTS.md` only if neither exists. **Team-owned targets are dropped at classification** (monorepo `CLAUDE.md`, its tracked `.claude/skills/*`): never a proposal or popup option, one line "not materialized (team-owned)" in the report |
| `skill-update` | edit `agent-skills/<name>/`; plugin skills (superpowers, skill-creator, …) go the upstream PR path, after confirming |
| `new-skill` | `agent-skills/<name>/SKILL.md`, no repo, no marketplace |
| `checkpoint` | `agent-skills/<name>/checkpoints.yaml` |
| `harness-artefact` | `.chezmoitemplates/claude-settings.json` or `dot_claude/hooks/`, never the rendered file |

- `~/.claude/CLAUDE.md` (stage 31) and `~/.claude/skills/` (stage 30, `--delete`) are generated: an edit there dies on the next `bin/sync`. Retro reports these skills as "user-local, no repo_url": never ask "edit locally or scaffold?", the answer is `agent-skills/`.
- After materializing, `bin/sync`. A new `agent-rules/*.md` needs `---` / `description: …` / `alwaysApply: true` / `---` or stage 31 skips it silently (dffe800a); then `rg -c '<rule title>' ~/.claude/CLAUDE.md` must not be 0.
- **Public repo:** evidence never carries a coworker's name or login: `<login>`, `<imię>` or the role.
- **No PR flow:** commit on `master` via `g-commit` and the end-of-task popup. No `feat/retro-*` branch, no `-s`, no `Learning-Id:` trailer (it may live in the rule text).
- **Memory is not a destination:** facts go to Hindsight (`memory-location.md`); `/retro promote` has nothing to drain.

## Signal filtering (Polish user)

- **A6** (EN+DE correction regex): Polish `no` = "well", every hit was a false positive. Unverified until the LLM pass. Real openers: `nie, `, `nie rób`, `nie tak`, `przestań`, `źle`, `miałem na myśli`, `chodziło mi o`, `(już) mówiłem`.
- **A18** counts command shapes, not prompts. Browsentic refusals are by design (`browser-stacks.md`), never propose loosening; `git commit` doesn't prompt. Allowlist candidates → `/g-allow-add`.
- **A9** is noise; skip.
- **REPL transcripts:** inner Bash/Read calls are logged again after each `REPL`, so A2, A4, A5, A11, A18, A19 double-count until the LLM pass (cd881b89).
- **A10** (skill mentioned, not invoked) = "a skill didn't fire": always surface it.

## Nudge and modes

- `dot_claude/hooks/retro-pending.sh` records sessions with ≥6 prompts or ≥40 tool calls in `~/.local/state/dotfiles/retro-pending.tsv`; SessionStart prints one total line. Mention it in one line, never list ids per repo. A session that ran `/retro` clears every id it named or touched (reading `<id>.jsonl` counts).
- **`/retro` on a fresh session:** nothing to sweep; if pending ids exist, sweep the newest pending transcript and say so, don't ask.
- **Session < 24 h → Sweep, not Outcome** (Outcome needs reverts/CI/merges to look at). Find the transcript by an exact phrase Greg typed (`grep -qF`), never by mtime.
- **Backlog in bulk → `/retro-backlog`** (`bin/retro-backlog`): `claude -p --model sonnet --max-turns 60 --disallowedTools Write Edit "/retro outcome <id> — PROPOSE ONLY …"` per session, 6 parallel, ~40–100 s each, outputs in `~/.local/state/dotfiles/retro-backlog/<date>/`. Sonnet does the pass, the interactive session decides. Output <~1 KB is a stub → re-run that id. Sessions < 24 h get "run as Sweep".
- **Retro scripts need Python ≥3.10:** `/usr/bin/python3` is 3.9 and `detect-mechanical.py` dies on `itertools.pairwise` (looks like "no signals"). Use `/opt/homebrew/bin/python3 -I <script>`, never a pinned `python3.X`. `bin/retro-backlog` puts `/opt/homebrew/opt/python3/bin` first on PATH.
- Slash commands appear in transcripts as `<command-name>/retro:retro</command-name>` + `<command-args>…`: grep that shape.
- Reports → `~/Code/personal/bazgroly/<repo>/analysis/YYYY-MM-DD-retro-<slug>.md`.
